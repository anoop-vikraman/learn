# 01 · Setup and your first app

## 1. What you need

> **In short:** Node.js, a phone with Expo Go (or a simulator), and nothing else to start — Xcode/Android Studio only become necessary for local native builds.

| Target | Needs |
| --- | --- |
| **Physical device** | The **Expo Go** app (iOS App Store / Play Store), same Wi-Fi as your computer |
| **iOS Simulator** | macOS + Xcode (free, large download) |
| **Android Emulator** | Android Studio + an AVD |
| **Cloud builds** | Nothing locally — **EAS Build** compiles on Expo's servers (even iOS builds from Windows/Linux) |

Start with a physical device: it's the fastest feedback loop and shows real performance.

## 2. Creating an app

> **In short:** `create-expo-app` scaffolds a TypeScript project with Expo Router and example screens.

```bash
npx create-expo-app@latest TaskMate
cd TaskMate
npx expo start                 # press i (iOS sim), a (Android), or scan the QR code with your phone
```

```bash
npx create-expo-app@latest TaskMate --template blank-typescript   # minimal, no example screens
```

```
TaskMate/
  app/                    # Expo Router: files here are screens
    _layout.tsx           # root layout (navigators, providers)
    index.tsx             # the "/" screen
    (tabs)/               # tab group
  assets/                 # images, fonts
  components/
  constants/
  app.json                # app config: name, icon, splash, plugins, permissions
  package.json
  tsconfig.json
```

## 3. Expo vs bare React Native

> **In short:** Use Expo unless you have a specific reason not to — you can still write native code, and you can eject later if you must.

| | Expo (managed, with CNG) | Bare React Native |
| --- | --- | --- |
| `ios/` and `android/` folders | Generated by `npx expo prebuild`, usually git-ignored | Committed and maintained by you |
| Native libraries | Config plugins; most work automatically | Manual Podfile/Gradle edits |
| Upgrades | `npx expo install --fix`, regenerate native projects | Manual, often painful |
| Builds | EAS Build (cloud) or local | Xcode/Android Studio |
| OTA updates, push, submissions | Built in | Assemble yourself |

**Continuous Native Generation (CNG)** is the key idea: your native projects are *derived* from `app.json` + plugins, like `node_modules` is derived from `package.json`. Delete and regenerate them any time.

## 4. Expo Go vs development builds

> **In short:** Expo Go is a shared sandbox for learning; a development build is your own app binary with your native dependencies — use it as soon as you add a library with native code.

```bash
npx expo install expo-dev-client
eas build --profile development --platform ios      # or android
# install the resulting build on your device/simulator, then:
npx expo start --dev-client
```

Signs you need a development build: a library's install instructions mention `pod install`, a config plugin, or "not supported in Expo Go".

## 5. Running and reloading

> **In short:** Save a file and Fast Refresh updates the app in place; shake the device (or press `m`) for the dev menu.

| Action | How |
| --- | --- |
| Fast Refresh | Save a file (preserves state where possible) |
| Full reload | `r` in the terminal, or dev menu → Reload |
| Dev menu | Shake the device, `m` in the terminal, `⌘D` (iOS sim), `⌘M`/`Ctrl+M` (Android emulator) |
| Open debugger | `j` in the terminal → React Native DevTools |
| Toggle the element inspector | Dev menu → Inspect |
| Clear the cache | `npx expo start -c` |

⚠️ If something behaves strangely after installing a package, clear the Metro cache first — it fixes a surprising share of problems.

## 6. `app.json` / `app.config.ts`

> **In short:** One config file describes your app's identity, icons, permissions and native plugins; `app.config.ts` lets you compute values and read environment variables.

```json
{
  "expo": {
    "name": "TaskMate",
    "slug": "taskmate",
    "version": "1.0.0",
    "orientation": "portrait",
    "icon": "./assets/icon.png",
    "scheme": "taskmate",
    "userInterfaceStyle": "automatic",
    "newArchEnabled": true,
    "splash": { "image": "./assets/splash.png", "resizeMode": "contain", "backgroundColor": "#0f172a" },
    "ios": { "supportsTablet": true, "bundleIdentifier": "com.example.taskmate" },
    "android": {
      "package": "com.example.taskmate",
      "adaptiveIcon": { "foregroundImage": "./assets/adaptive-icon.png", "backgroundColor": "#0f172a" },
      "edgeToEdgeEnabled": true
    },
    "plugins": ["expo-router", ["expo-camera", { "cameraPermission": "TaskMate uses the camera to attach photos to tasks." }]],
    "experiments": { "typedRoutes": true }
  }
}
```

```ts
// app.config.ts — dynamic config
import type { ExpoConfig } from 'expo/config';

export default ({ config }: { config: ExpoConfig }): ExpoConfig => ({
  ...config,
  name: process.env.APP_VARIANT === 'dev' ? 'TaskMate (Dev)' : 'TaskMate',
  ios: { ...config.ios, bundleIdentifier: process.env.APP_VARIANT === 'dev' ? 'com.example.taskmate.dev' : 'com.example.taskmate' },
  extra: { apiUrl: process.env.EXPO_PUBLIC_API_URL },
});
```

⚠️ `bundleIdentifier`/`package` are permanent once published to the stores — choose carefully.

## 7. TypeScript

> **In short:** TypeScript is the default; `npx expo install` keeps library versions compatible with your SDK.

```bash
npx expo install expo-router react-native-safe-area-context    # ✅ SDK-compatible versions
npm install some-library                                        # ⚠️ may install an incompatible version
npx expo install --check                                        # report mismatches
npx expo install --fix                                          # fix them
```

```json
// tsconfig.json (generated)
{
  "extends": "expo/tsconfig.base",
  "compilerOptions": { "strict": true, "paths": { "@/*": ["./*"] } }
}
```

## 8. Your first screen

> **In short:** A screen is a React component that returns native components — the same mental model as React, with different primitives.

```tsx
// app/index.tsx
import { useState } from 'react';
import { View, Text, TextInput, Pressable, FlatList, StyleSheet } from 'react-native';
import { SafeAreaView } from 'react-native-safe-area-context';

type Task = { id: string; title: string; done: boolean };

export default function HomeScreen() {
  const [tasks, setTasks] = useState<Task[]>([]);
  const [title, setTitle] = useState('');

  function addTask() {
    const trimmed = title.trim();
    if (!trimmed) return;
    setTasks((prev) => [...prev, { id: String(Date.now()), title: trimmed, done: false }]);
    setTitle('');
  }

  return (
    <SafeAreaView style={styles.container} edges={['top']}>
      <Text style={styles.heading}>TaskMate</Text>

      <View style={styles.row}>
        <TextInput
          style={styles.input}
          value={title}
          onChangeText={setTitle}
          placeholder="What needs doing?"
          returnKeyType="done"
          onSubmitEditing={addTask}
        />
        <Pressable style={styles.button} onPress={addTask} accessibilityRole="button">
          <Text style={styles.buttonText}>Add</Text>
        </Pressable>
      </View>

      <FlatList
        data={tasks}
        keyExtractor={(item) => item.id}
        renderItem={({ item }) => <Text style={styles.item}>{item.title}</Text>}
        ListEmptyComponent={<Text style={styles.empty}>No tasks yet</Text>}
      />
    </SafeAreaView>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, padding: 16, backgroundColor: '#fff' },
  heading: { fontSize: 28, fontWeight: '700', marginBottom: 16 },
  row: { flexDirection: 'row', gap: 8, marginBottom: 16 },
  input: { flex: 1, borderWidth: 1, borderColor: '#cbd5e1', borderRadius: 8, padding: 12 },
  button: { backgroundColor: '#4f46e5', borderRadius: 8, paddingHorizontal: 16, justifyContent: 'center' },
  buttonText: { color: '#fff', fontWeight: '600' },
  item: { paddingVertical: 12, borderBottomWidth: 1, borderBottomColor: '#e2e8f0' },
  empty: { color: '#64748b', textAlign: 'center', marginTop: 32 },
});
```

Differences from the web to notice: every string lives inside `<Text>`, `onPress` not `onClick`, `onChangeText` gives you the value directly, and styles are objects with no units.

## 9. Debugging

> **In short:** React Native DevTools for components and the console, plus platform profilers for deeper work.

| Tool | Use |
| --- | --- |
| **React Native DevTools** (`j` in the terminal) | Console, component tree, profiler, network, breakpoints |
| `console.log` | Appears in the terminal running Metro |
| Element inspector | Tap a view to see its styles and hierarchy |
| **Xcode Instruments / Android Studio Profiler** | Native CPU, memory, startup |
| **Sentry / Bugsnag** | Crashes and errors from real users |
| LogBox | Warnings/errors shown in-app during development |

## 10. Environment variables

> **In short:** Variables prefixed `EXPO_PUBLIC_` are inlined into the JS bundle; anything secret must live on your server, never in the app.

```bash
# .env
EXPO_PUBLIC_API_URL=https://api.example.com
```

```ts
const apiUrl = process.env.EXPO_PUBLIC_API_URL;
```

⚠️ **There are no secrets in a mobile app.** Anyone can unzip an IPA/APK and read the bundle. API keys that must stay private belong behind your backend.
